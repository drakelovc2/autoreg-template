# autoreg-template

> **Одна строка:** переиспользуемый Python-скелет для регистрации и подтверждения почты на сервисах, которые вам принадлежат или которые вы официально уполномочены тестировать.

## Что это и зачем

Каждый новый «авторег» начинается одинаково: форма, письмо с кодом или ссылкой, прокси, ключ, банк аккаунтов, панель. Писать это с нуля в пятый раз — больно и приводит к разным багам в каждом реггере.

Этот шаблон закрывает скучную часть: контракт адаптера, чтение почты, прокси, локальную панель, атомарное хранение аккаунтов и self-тесты. Вы реализуете только сервис-специфику в одном файле `core/register.py`.

> **Ответственное использование.** Только свои сервисы или письменное разрешение владельца. Против сторонних сервисов это может нарушать их условия и закон. См. [TERMS.md](TERMS.md).

## Что умеет

- **Один контракт:** `register_one()`, `test_key()`, `list_models()` — панель и банк работают с любым адаптером.
- **HTTP и браузер:** `requests` для протокольных флоу, Camoufox/Playwright для форм и капчи.
- **Почта:** catch-all через admin API (apimail / [@apimaildrakebot](https://t.me/apimaildrakebot)), Gmail-алиасы через IMAP, точка расширения под свой провайдер. В `apimail/` — исходники панели для своего catch-all движка. Подробнее — `docs/APIMAIL.md`.
- **Прокси:** статические списки, ротация сессий, ISP-зоны, отдельный exit-IP на аккаунт.
- **Панель:** запуск/стоп прогонов, прогресс по воркерам, список аккаунтов, логи.
- **Атомарный банк:** JSONL + combo-файл, межпроцессный лок, идемпотентная запись по email.
- **Двухфазный флоу:** `output_pending` для аккаунтов, созданных но ещё не подтверждённых.
- **Self-тесты и mock-сайт:** проверка без внешнего сервиса.

## Чего нет

- Кредов, API-ключей, прокси-аккаунтов и ящиков.
- Адаптеров под конкретные сервисы (они в примерах ниже).
- Ключей капча-солверов — только пустой хук.
- Аккаунтов, cookies и сессий.

## Требования

| Что | Версия | Зачем |
|---|---|---|
| Python | 3.10+ | рантайм |
| requests | ≥2.31 | HTTP-флоу |
| Camoufox или Playwright | по желанию | браузерные флоу |

## Установка и запуск

### Linux / macOS

```bash
cp config.example.json config.json
# заполнить base_url, mail_*, proxies
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python3 tests/selftest_browser.py
bash start.sh          # панель на 127.0.0.1:9900
```

### Windows

```bat
start.bat
```

`start.bat` сам создаёт venv, ставит зависимости и копирует `config.example.json` в `config.json`. Останется заполнить конфиг.

## Структура

```
core/          движки + контракт адаптера (начинать с core/register.py)
panel/         локальная панель
bridge/        опциональные помощники пула ключей
apimail/       исходники панели для своего catch-all движка
tests/         self-тесты
tools/         recon и mock-сайт
examples/      два минимальных адаптера: HTTP-OTP и браузер+Turnstile
docs/          ARCHITECTURE.md, APIMAIL.md и STANDARD.ru.md
SKILL.md       точка входа для агентов
TERMS.md       acceptable use
```

## Примеры

В `examples/` лежат два адаптера-образца:

- `examples/http_otp/` — HTTP-only: запрос кода, чтение письма, подтверждение, ключ.
- `examples/browser_turnstile/` — браузер: форма, ожидание Turnstile-токена, сабмит.

Реальные проекты с такой же структурой (реггер + мост) лежат в этом же `githubsources/`:

- `classifier-autoreg-2api`
- `backboard-autoreg-2api`
- `gooey-autoreg-2api`
- `postman-autoreg-2api`

Они показывают, как один и тот же контракт масштабируется до полноценного репозитория `<сервис>-autoreg-2api`.

## Ограничения

- Шаблон не проходит капчу «из коробки»: нужен свой солвер или ручной шаг.
- Часть сервисов не принимает временные домены почты — используйте свой catch-all или Gmail.
- Прокси-пулы и почтовые провайдеры не входят в комплект.
- Лимиты и антифрод конкретного сервиса нужно выяснять самостоятельно.
